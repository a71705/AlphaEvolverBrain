#### **3. 数据持久化细节 - 缺失 Alpha 表达式版本控制和历史追踪**

*   **您的观察:** 缺失 Alpha 表达式的版本控制和历史追踪。
*   **我的分析:** `DEV-008` 中定义的 `Alpha` 模型包含 `id`, `expression`, `depth`, `iteration`, `parent_ids`。
    *   `expression` 字段本身就存储了 Alpha 表达式的“版本”，因为每次遗传算法生成一个新的表达式，就会是一个新的 `Alpha` 记录。
    *   `iteration` 字段关联了 Alpha 生成的代数，这有助于追踪它的历史。
    *   `parent_ids` 则直接提供了其血缘关系（如果该 Alpha 是通过交叉或变异从其他 Alpha 演变而来）。
    *   所以，**基本的历史追踪和“版本”信息已经存在于 `Alpha` 模型中。** 如果您的“版本控制”是指类似 Git 那样对单个 Alpha 的代码进行修改和回溯，那在遗传编程中并不常见，因为通常是生成新个体而非修改旧个体。如果是指追踪某个“最佳 Alpha”随着时间演化的具体参数调整，那可能需要更精细的模型或日志。
*   **结论:** 基本的历史追踪已覆盖。更复杂的“版本控制”是一个高级特性，可以作为未来增强。
*   **建议补全:** 我将在 `DEV-008` 的描述中明确指出 `iteration` 和 `parent_ids` 的作用，并（可选）添加一个高级任务来探讨更复杂的版本控制需求。

    # app/core/gp_algo.py
    def combine_alphas(alpha_expressions: List[str], method: str = "add") -> str:
        if not alpha_expressions:
            return ""
        if len(alpha_expressions) == 1:
            return alpha_expressions[0]

        combined_expr = ""
        if method == "add":
            combined_expr = f"add({alpha_expressions[0]}, {alpha_expressions[1]})"
            for expr in alpha_expressions[2:]:
                combined_expr = f"add({combined_expr}, {expr})"
        elif method == "mean": # Example for mean
            # mean(expr1, expr2, ...) is not a direct WQ Brain op, usually it's add(expr1, expr2)/2
            # For simplicity, if platform has no "mean" op, use nested add/divide
            # Or assume a 'mean' operator in WQ Brain. For generic, it's (add(expr1,expr2,...))/N
            sum_expr = alpha_expressions[0]
            for expr in alpha_expressions[1:]:
                sum_expr = f"add({sum_expr}, {expr})"
            combined_expr = f"divide({sum_expr}, {len(alpha_expressions)})"
        # Add other methods like "multiply", "min", "max" if applicable and supported by WQ Brain
        
        return combined_expr
